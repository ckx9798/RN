## 작업 배경

기존 `AGENTS.md`에 Expo, 플랫폼, 구조, 상태와 커밋 규칙이 함께 들어
있었지만 Git 브랜치·PR 운영, 문서 보관, 배포와 보안 규칙은 충분히
정의되지 않았다. 승인된 FSD 설계와 기존 디렉터리 안내도 서로 다른
구조를 설명하고 있었다.

## 작업 목표

사람과 AI 에이전트가 같은 규칙을 찾고 적용할 수 있도록 루트 진입
문서와 주제별 상세 규칙을 분리한다. FSD 목표 구조와 PR 단위 작업 이력,
명사형 커밋 메시지 기준을 프로젝트의 공식 규칙으로 확정한다.

## 작업 범위

- 프로젝트 소개와 실행 방법을 실제 저장소 기준으로 갱신
- AI 에이전트 핵심 지침과 규칙 우선순위 정리
- 기여자의 Git·PR 실행 순서 추가
- FSD 아키텍처 상세 규칙 추가
- Expo 개발, 검증, 보안과 EAS 배포 규칙 추가
- 문서 분류, Superpowers 기본 경로와 PR별 이력 규칙 추가
- PR 작업 이력 템플릿 추가

## 주요 변경 사항

### 진입 문서

Expo 기본 템플릿 README를 Expo SDK 57, React Native 0.86과
iOS·Android 범위를 설명하는 프로젝트 안내로 교체했다. `AGENTS.md`는
사용자가 작성한 Expo·모바일 규칙을 보존하면서 FSD 구조와 상세 규칙
링크를 기준으로 재구성했다.

### 상세 규칙

`docs/rules/`를 아키텍처, 개발, Git·PR, 문서 관리와 배포 책임으로
분리했다. 루트 문서는 실행에 필요한 요약만 제공하고 상세 기준은 해당
규칙 문서 한 곳에서 관리하도록 했다.

### PR 작업 이력

설계와 구현 계획은 `docs/superpowers/` 기본 경로에 유지한다. 구현
결과는 Draft PR 번호를 확보한 뒤
`docs/history/YYYY-MM-DD-pr-<number>-<topic>.md` 형식으로 같은 PR에
기록하도록 정했다.

## 핵심 기술 결정

- 프로젝트 구조는 `app → pages → widgets → features → shared` 방향의
  축소 FSD를 사용한다.
- `src/app/`은 Expo Router 라우트와 앱 초기화만 담당한다.
- 문서 전용 변경은 코드 검증 명령의 자동 설치를 피하고
  `git diff --check`와 링크·경로·명령어로 검증한다.
- commit, push, PR 생성, Ready 전환, 병합과 배포는 각각 별도 권한으로
  구분한다.
- 커밋과 PR 제목은 명령형이 아닌 명사형 결과를 사용한다.

## 사용자 영향

애플리케이션 화면과 동작 변화는 없다. 이후 개발과 협업 작업에서
적용할 구조, 검증, Git·PR과 문서 관리 기준이 추가됐다.

## 검증 결과

- 전체 로컬 Markdown 링크 검사: 통과
- 미완성 표현 검사: 통과
- `git diff --check`: 통과
- 계획 Task 1~6 구조 검증: 모두 통과
- lint와 typecheck: 앱 코드를 변경하지 않은 문서 전용 PR이므로 실행하지
  않음
- 최종 독립 리뷰: 사용자 요청으로 생략
