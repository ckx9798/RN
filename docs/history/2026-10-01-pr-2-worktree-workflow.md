## 작업 배경

기존 규칙은 여러 목적의 변경이 섞일 위험이 있을 때만 worktree 사용을
권장했다. 이 기준으로는 `main` 작업공간의 미완료 변경과 새 작업이
섞이거나 병렬 작업이 서로 영향을 주는 상황을 일관되게 방지하기
어려웠다.

## 작업 목표

저장소 파일을 변경하는 모든 작업을 최신 `main`에서 분리한 새
worktree와 목적별 브랜치에서 시작한다. 구현 결과는 PR을 거쳐
`main`에 병합하는 순서를 프로젝트 공통 규칙으로 확정한다.

## 작업 범위

- AI 에이전트의 핵심 Git 작업 지침 갱신
- 기여자 작업 체크리스트에 worktree 생성 단계 추가
- 상세 Git·PR 규칙에 필수 작업 흐름과 예외 추가
- 외부 상태 변경별 승인 경계 유지

## 주요 변경 사항

`AGENTS.md`, `CONTRIBUTING.md`, `docs/rules/workflow.md`에서 파일 변경
작업의 시작 위치와 종료 흐름을 일치시켰다. 최신 `main`에서 새
worktree와 목적별 브랜치를 만들고 구현·검증, commit, push, PR,
`main` 병합 순서로 진행하도록 명시했다.

읽기 전용 분석과 상태 확인은 파일을 변경하지 않으므로 새 worktree를
요구하지 않는다. worktree 사용 규칙이 commit, push, PR 생성, Ready
전환, 병합이나 브랜치 삭제 권한을 자동으로 부여하지 않는다는 경계도
함께 기록했다.

## 핵심 기술 결정

- worktree 사용을 상황별 권장이 아닌 모든 파일 변경 작업의 필수
  조건으로 적용한다.
- 작업 기준은 로컬 상태가 아니라 최신 원격 `main`으로 통일한다.
- 격리된 작업공간 사용과 외부 상태 변경 승인은 별개의 규칙으로
  유지한다.
- 앱 코드와 저장소 파일을 바꾸지 않는 읽기 전용 작업은 예외로 둔다.

## 사용자 영향

애플리케이션 화면과 동작 변화는 없다. 이후 저장소 변경 작업은 별도
worktree와 PR을 거쳐 `main`에 반영된다.

## 검증 결과

- 필수 worktree·PR·`main` 병합 문구 검사: 통과
- 기존 선택적 worktree 문구 제거 검사: 통과
- 전체 추적 대상 Markdown 로컬 링크 검사: 통과
- `git diff --check`: 통과
- lint와 typecheck: 앱 코드를 변경하지 않은 문서 전용 PR이므로 실행하지
  않음
